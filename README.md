Architecture. A conversational agent that behaves like an environmental scientist rather than an LLM wrapper. Input (free text or JSON, optionally coordinates) is parsed into a site profile and stored in session memory. The agent asks targeted clarifying questions until at least three variable families are known (soil, climate/water, land use, biodiversity, human impact). A rule engine then diagnoses co-occurring stressors, ranks interventions by how many stressors each relieves, and explains the causal chain. A hybrid retriever (TF-IDF, plus sentence embeddings when installed) over evidence cards and ingested papers supplies the citations; the retrieval trace is returned with every answer.
Output per recommendation: action, why it works (reasoning chain using the user's own numbers), impacted metrics, expected effect with source figures, time horizon (short/medium/long), confidence with its reason, caveats, and DOI citations. It also lists options it deliberately rejected and why (for example, cover crops in a semi-arid, low-rainfall site because they compete for water).
Database/schema. SQLite: sessions(id, profile_json, last_recs_json, pending_questions_json, timestamps) and messages(id, session_id, role, content, created_at). Knowledge is versioned YAML (kb/evidence.yaml, kb/interventions.yaml) plus kb/docs for PDFs; the vector index is rebuilt from it at start-up.
Local setup. pip install -r requirements-dev.txt; python -m app.ingest; uvicorn app.main:app --reload; open http://localhost:8000. Tests: pytest -q (18 tests, fully offline). Docker: docker build -t bio-agent . && docker run -p 8000:8000 bio-agent.
CI/CD. GitHub Actions runs ruff, builds the index, runs pytest and builds the Docker image on every push and PR. Pushes to main trigger a Render deploy hook (stored as a GitHub secret) that redeploys the Docker service defined in render.yaml.
